# 에이전트팀 모드

`subagent-driven-development`를 Agent Teams로 실행하는 절차임. 모드 판정과 팀 공통 규칙(리드 = 메인 세션, 최대 5명, 같은 파일 동시 편집 금지, 종료 요청, 재개 시 재스폰)은 `using-my-poor-ai`의 `references/agent-teams.md`가 정본임 — 여기서는 SDD 고유 차이만 다룸.

## 바뀌는 것과 유지되는 것

| 항목 | 서브에이전트 모드 | 팀 모드 |
| --- | --- | --- |
| 구현자 | 작업마다 새 서브에이전트 | 작업마다 새 팀원 `impl-{작업번호}` (작업 간 컨텍스트 오염 방지 원칙 유지) |
| 검토자 | 검토 때마다 새 서브에이전트 | 상주 팀원 2명: `spec-reviewer`, `quality-reviewer` — 실행 전체에서 재사용 |
| 이슈 전달 | 컨트롤러가 검토 결과를 구현자에게 중계 | 검토자가 구현자에게 직접 `SendMessage`, 구현자는 수정 후 같은 검토자에게 재검토 요청 |
| 컨트롤러 역할 | 모든 왕복 중계 | 작업 배정·순서 게이트·완료 판정만 |

**유지되는 규칙 (모드 무관):**

- 스펙 준수 ✅ 전에 코드 품질 검토 시작 금지 — 리드는 `spec-reviewer`의 승인 메시지를 받은 뒤에만 `quality-reviewer`에게 검토를 지시함
- 구현자는 **동시에 1명** — 병렬 구현자는 충돌을 일으킴
- 구현자에게 작업 전체 텍스트와 컨텍스트를 직접 제공 (플랜 파일을 읽히지 않음)
- 검토 루프는 승인까지 반복, 재검토 생략 금지
- 프롬프트는 같은 템플릿(`./implementer-prompt.md`, `./spec-reviewer-prompt.md`, `./code-quality-reviewer-prompt.md`)을 씀. 상주 검토자에게는 작업마다 해당 작업의 요구사항·SHA를 `SendMessage`로 보냄

## 작업별 흐름

1. 리드: `impl-{N}` 스폰 (작업 텍스트 + 컨텍스트)
2. `impl-{N}`: TDD → 커밋 → 리드에게 상태 보고 (DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED 처리 규칙은 SKILL.md와 동일)
3. 리드: `spec-reviewer`에게 작업 N 검토 지시
4. `spec-reviewer` ↔ `impl-{N}`: 이슈 직접 왕복 → 승인 시 리드에게 보고
5. 리드: `quality-reviewer`에게 작업 N 검토 지시 → 같은 방식으로 왕복 → 승인 보고
6. 리드: `impl-{N}` 종료 요청, 플랜 체크박스 갱신, 다음 작업

모든 작업 완료 후 최종 코드 검토는 `quality-reviewer`에게 전체 범위로 지시하고, 이후 검토자 2명에게 종료를 요청함.

## 흔한 실수

| 실수 | 대안 |
| --- | --- |
| 검토자끼리 직접 협의해 품질 검토를 스펙 검토와 동시에 시작 | 순서 게이트는 리드가 쥠 — 승인 보고 후에만 다음 단계 지시 |
| 구현자 팀원을 여러 작업에 재사용 | 작업마다 새 팀원 — 이전 작업 컨텍스트가 섞임 |
| 리드가 검토 이슈를 직접 수정 | 구현자가 수정함 (컨텍스트 오염 방지 규칙 동일) |
